# Camelot-OS VPS Hub North Star

**Scope:** Cybertronia primary 8 GB VPS Hub  
**Binding baseline:** `CAMELOT-OS-SADD-LLDD-vMAX-20260912` v2.0.0

## Mission

The VPS Hub is the active authority and coordination plane for Camelot-OS. It turns authenticated user intent into bounded, tenant-scoped, evidence-backed outcomes without allowing models, cartridges, workers, browsers, or network connectivity to manufacture authority.

## Outcome contract

`Intent → typed plan → Sentinel policy decision → immutable manifest → Excalibur approval when required → manifest-bound lease → VFS preflight → bounded execution → Gideon verification → Arthur resolution → Ledger receipt → verified UI projection`

The Hub is complete only when the visible system state can be traced back to authoritative events and signed receipts.

## Primary responsibilities

- Host the active Sentinel policy, lease and revocation authority.
- Host Bifrost trust and transport admission.
- Host Excalibur approval workflow for consequential manifests.
- Host Gideon independent verification and Arthur final resolution.
- Preserve immutable Ledger receipt-chain evidence.
- Coordinate PostgreSQL, SQLite-VSS, MinIO and ephemeral Redis within tenant scope.
- Admit Wasmtime Pills and Firecracker evaluation workloads under explicit capabilities.
- Render verified workspace projections to Ecoshell / World Tree without fabricating authority state.
- Maintain the 8 GB scarcity envelope and shed non-critical work before authority services.

## Non-goals

The VPS Hub is not:

- a generic remote shell,
- an open proxy,
- a container orchestration cluster,
- a browser-to-database application,
- a place for Python or Node authority services on the production hot path,
- a single giant agent with ambient access,
- a home for unrestricted cross-tenant retrieval,
- an execution authority for Watchtower or visualization components,
- an autonomous policy editor,
- a self-promoting learning system.

## Experience principle

The Hub experience may be spatial, cinematic and immersive, but the visual world is a **projection of verified state**. World Tree, Battle Mode, Shadow Subspace and future cinematic scroll surfaces must distinguish simulation, proposal, pending approval, verified execution and receipted completion.

The experience may use progressive 2D→3D motion, scroll-scrubbed camera transitions and mobile-specific compositions, but reduced-motion and semantic DOM representations are mandatory. Cinematic rendering never becomes an authority source.

## Integration doctrine

External ecosystem repositories are integrated as bounded capabilities, not promoted into core authority:

- QtScrcpy → device-action cartridge / actuator surface.
- t3code → compiler cartridge in approved workspace.
- jcode → AST analysis/execution cartridge under VFS scope.
- skillscript → skill interpreter candidate, admitted and versioned like any other cartridge.
- Fonoster → communications cartridge behind consent, suppression, Excalibur and receipts.
- Multivoice-router → governed voice/identity handoff through Bifrost.
- Graphiti/legacy Neo4j/Qdrant integrations → optional adapters or migration sources; P0 Cloudbrain authority uses scoped SQLite-VSS per the binding v2.0 baseline.

## Definition of converged

The Hub is `CONVERGED` when all production release gates are green, including authority-chain tests, cross-tenant fail-closed tests, lease expiry/revocation, exact-manifest approval binding, receipt-chain validation, VFS denial fixtures, resource ceilings, backup/restore, Twin-Brain promotion drill and documentation traceability.
